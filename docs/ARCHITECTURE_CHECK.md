# 中文交互与架构核查

核查日期：2026-11-25。对象为当前工作目录的实现及本机配置。

## 本次交互调整

- 新任务和聊天统一使用简体中文，不受用户输入语言、自定义角色语言或“请用英文回答”的要求影响。专有名词、代码标识符、数据字段、URL、引用原文及用户原始记录保留原样。
- 每轮澄清只问一个关键问题，限一行、100 字；选择题提供 2–3 个选项，每项最多 30 字，也可自行填写一句话。推荐项不会自动提交。
- 提示词要求对可逆的小偏好采用合理默认值，普通偏好尽量在两轮内澄清；确实影响正确性的信息仍需询问。两轮是模型行为指导，不是强行跳过必要澄清的限制。
- 执行中得到的回答进入整个任务的共享澄清记录，后续 Agent 可复用；重复询问同一个已回答问题会被控制器拒绝。
- 规划阶段的不合规提问进入最多三次修正流程；执行阶段沿用有预算的失败反馈与修正。聊天明显非中文、过长或包含多个问号时最多修正一次，不增加无限重试。
- 中文策略覆盖所有真实模型提示词；提交 Markdown、TXT、HTML 时检查明显非中文的正文，HTML 检查排除脚本和样式。语言检查属于启发式防护，不能证明所有句子语义正确；代码和结构化数据不做强制翻译。
- 交付验收改成一个简短确认问题，原验收条件和文件版本完整保留在详情中。删除和发布仍须确认具体对象；选项回答不能代替批准。
- 团队页可切换群聊和四位 Agent 的私聊。私聊用于交流，协作执行从群聊发起。历史问题、旧交付和审计原文不会被改写。

**隔离要求的解释边界：** 调度、LLM 调用、文件工具、网络工具和 Git 由同一可信控制进程代理，任意生成代码才进入独立容器。当前满足“每位 Agent 独立工作区、生成代码独立沙箱”的实现边界；如果课程要求每个 Agent 的整个进程及所有工具都必须在独立容器内运行，当前架构尚不满足该更严格解释，不能报告为全部严格达标。

GitHub 实际验收前需在 `.env` 设置 `EVOTASK_GITHUB_REMOTE=https://github.com/用户名/仓库.git` 和具有对应仓库写权限的 `EVOTASK_GITHUB_TOKEN`，重启服务后由用户批准发布。系统仅允许专用 `evotask/<名称>` 分支，并拒绝覆盖内容不同的既有目标分支。
