# 中期测试适配与操作

实施要求见 [MID_TEST_IMPLEMENTATION.md](../MID_TEST_IMPLEMENTATION.md)，老师原题见 [Mid_Test/README.md](../Mid_Test/README.md)。原题作为输入资料，生产代码不预设三个场景的拆解、答案或技术选型。

本轮实际结果、未验收项目和证据位置见 [中期测试报告](MID_TEST_RESULTS.md)。

## 网页操作

1. 启动项目，打开 `http://127.0.0.1:8000`，进入「Agent 对话 → 新建团队」，填写团队名和四位成员的名称、职责。首位统筹，末位独立审查。
2. 在团队页面输入内容。「发送消息」只讨论；「发起任务」启动后台执行。真实模式会消耗模型额度。
3. 在任务卡片回答「等你回答」，或下载待审阅文件后批准/拒绝。刷新保留待处理问题，回复后继续原任务。
4. 延续交付时，在已完成任务上点击「基于这些文件发起新任务」，选择文件版本并填写新目标。普通同群任务也能获得有长度上限的历史上下文。
5. 从卡片或详情下载文件。HTML 在平台内按文本预览，下载后用浏览器打开。团队右上角可导出审计 JSON，或点击「导出评测包 ZIP」一次下载记录与全部归档产物。

任务失败后可「重新运行」：创建新运行，保留原角色和输入快照，使用最新同群上下文与经验。原失败记录保留；新运行重新获得原配置预算。动作格式兼容恢复入口仍在任务详情。

Verifier 依赖多个上游任务时，失败测试先冻结，再由 Verifier 明确指定返修对象。旧记录可在详情点击「修复并复验」继续选择，沿用原预算和最多两轮返修。群内新反馈会进入后续决策上下文；人工验收仍由实际确认决定，模型声称“已满足人工检查”不会自动通过。

规划返回自定义角色名称时，后端只在能唯一对应的情况下映射到内部位置。规划原文和校验错误会保留；格式错误最多纠正两次，并计入原模型与时间预算。未识别或含糊的角色不会被随意分派。

模型上下文会注明单次输出 token 上限。长文档与 HTML 可先写骨架，再通过 `update_file` 分段填充；模型响应被截断时不会执行其中的动作，错误反馈会提示缩短输出。此策略不提高原配置预算，也不能保证所有模型都遵循分段提示。

## 数据与权限

- 自定义团队使用后端确定的工具候选集。规划校验、竞标资格、实际执行使用同一份权限；职责文字不能授予额外权限。默认团队配置保留；删除和 Git 发布仍须审批。
- 运行固定角色快照；群聊和经验按账号/访客、模式、团队隔离。独立验证者不能验收自己的上游产物，筛选覆盖整条依赖链。
- 跨轮只能选择同群已完成运行的归档。原始相对路径、原始字节、版本和 SHA-256 被保留，文件进入 `inputs/previous/`。同路径多版本须选择一个。工具禁止改写输入；Docker 将输入目录只读挂载。新一轮修改工作副本，旧归档不变。
- 上传依旧走原文本提取流程；跨轮归档不经过转换。失败重跑检查输入哈希，沿用相同快照。网页源码支持 HTML、CSS、JavaScript；HTML 幻灯片应按任务要求自包含。
- 全量导出来自持久化记录，包含消息、角色快照、运行清单、任务、事件、人工回复、指标、交付文件清单、失败和经验。实际文件随评测包 ZIP 下载。页面只展示近期记录，导出包含全部已保存记录。
- 搜索默认 Wikipedia；通用网页搜索需要有效 Brave 配置。是否拿到近期、可靠且支持主张的来源，应与程序运行是否成功分别评价。

## 提交给外部模型评审

进入团队页面，点击右上角「导出评测包 ZIP」。也可通过当前登录会话访问 `GET /api/teams/{team_id}/evaluation.zip?mode=live`（演示模式使用 `mode=demo`）。无需重新运行任务，也不消耗模型额度。

解压后包含：

| 文件 | 内容 |
|---|---|
| `README.md` | 阅读顺序、文件说明及版本清单的使用方法 |
| `dialogue.md` | 按时间排列的已保存群聊与事件，附完整任务动作/工具结果、澄清、失败、人工状态和角色快照 |
| `audit.json` | 机器可读的原始审计数据 |
| `manifest.json` | 运行与产物状态、版本路径、字节数及 SHA-256；`current_task_output` 标识任务当前选定的版本 |
| `outputs/运行ID/产物ID/原路径` | 所有归档版本的实际内容，包括失败、未验收和已被替代的版本，保持原始字节 |

将对话、清单和相关产物一起交给 DeepSeek 或 ChatGPT。不要仅提交任务摘要或将 `verified` 当作整题质量合格。若评审服务不支持 ZIP，先在本地解压后上传它支持的文件。

导出不受页面最近 100 条消息、30 次运行的显示限制；归档缺失、路径非法或哈希不符时，会报错并中止下载。运行中也可以导出，但只代表当时保存的进度。

“完整”指已持久化的团队群聊、运行记录和归档版本；并非逐次 LLM API 原始请求/响应，不包含其他群、私聊、原始上传文件和整库知识库。历史上未记录或已经截断的内容无法追补。导出不会自动上传至任何评审服务。

## 回归与真实评测

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -q
.\.venv\Scripts\python.exe -m tests.browser_teams
$env:EVOTASK_DOCKER_TESTS = '1'
.\.venv\Scripts\python.exe -m unittest tests.test_docker_integration tests.test_collaboration -q
```

回归使用老师题目以外的博物馆团队，覆盖职责传递、群隔离、提问恢复、文件路径与字节保留、37 → 38 的数据延续、原归档不变、输入防篡改，以及 HTML 下载和前后翻页。可控响应验证框架流程，不代表真实模型完成老师原题。

真实测试辅助程序 `tests/mid_test_ui.py` 通过普通界面录入老师角色与原题，不自动回答问题或批准产物。先查看实际问题，再准备回答文件，通过 `reply` 提交。软件组第二题从第一题交付卡片继承文件；三组依次执行。

已有中期测试账号和团队记录时，可用 `python -m tests.mid_test_ui package --scenario 1` 从网页下载并校验该组评测包；将 `1` 换成 `2` 或 `3` 下载其他组。此命令不会启动任务或模型请求。

真实测试账号、会话、截图和审计导出位于被 Git 忽略的 `test-results/mid-test/`；不要提交其中的登录信息或浏览器状态。评测报告分别记录框架检查、人工验收和外部质量验证，保留失败、未完成和待人工状态。

`export` 会下载各次运行的全部归档版本并核对 SHA-256，按 `scenario-N/运行ID/archive/产物ID/原路径` 保存。当前已验证版本另存于 `scenario-N/运行ID/原路径`，便于检查。审计 JSON 中的 `verified` 仅表示通过了该子任务声明的检查，不代替整题人工验收。
